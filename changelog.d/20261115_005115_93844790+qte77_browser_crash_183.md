### Fixed

- The patchright tier no longer lets a crashed render target escape `fetch()` as a raw
  `patchright._impl._errors.Error` ("Target crashed" / "Page crashed"), breaking the
  library's typed-error contract. `_run_page` now detects a crash by the error message
  (Patchright never raises a distinct type for it, and `page.on("crash")` does not
  reliably fire — verified locally) and treats it as a retryable failed attempt inside
  the existing `RetryPolicy` loop, the same as a navigation timeout; each attempt already
  gets a fresh context, so a crashed page is simply discarded on retry. The browser
  process itself is relaunched only when `browser.is_connected()` is `False` — a crashed
  renderer alone does not disconnect it. Once every attempt crashes, `fetch()` raises the
  new `BrowserCrashed` (a `FetchError` subclass), chained from the last Patchright error,
  instead of the raw exception. Any other Patchright error is unaffected (#183).
