### Fixed

- The patchright tier no longer lets a crashed render target escape `fetch()` as a raw
  `patchright._impl._errors.Error` ("Target crashed" / "Page crashed"), breaking the
  library's typed-error contract. `_run_page` now detects a crash by the error message
  (Patchright never raises a distinct type for it; detection is by message, not event) and
  treats it as a retryable failed attempt inside the existing `RetryPolicy` loop, the same
  as a navigation timeout; each attempt already gets a fresh context, so a crashed page is
  simply discarded on retry. A crash surfacing while the page is being re-read during a
  client-side-redirect recovery (`_read_content`'s second branch) is re-raised unwrapped
  instead of being buried inside a generic `FetchError`, so it is still recognized and
  retried. Any other Patchright error is unaffected.
- A whole-browser-process death (not just one crashed render target) is now covered too:
  `_attempt_once` raising any `PwError` (e.g. `TargetClosedError`, whose own message never
  says "crashed") while `browser.is_connected()` is `False` is treated the same way — a
  crashed renderer alone does not disconnect the browser, so a `PwError` while it is still
  connected keeps propagating unchanged. The browser is relaunched only in that
  disconnected case (the old handle is closed best-effort first); if the relaunch itself
  fails, `fetch()` raises the typed error instead of a raw launch failure. Once every
  attempt ends this way (crash-phrase match or a disconnected browser), `fetch()` raises
  the new `BrowserCrashed` (a `FetchError` subclass), chained from the last Patchright
  error, instead of the raw exception (#183).
